**Rule 1 — Response type mapping (strict):**
- `ctx.ok()` → success only (action completed, thing was created/changed/deleted)
- `ctx.err()` → errors only (permission denied, not found, invalid input, failed)
- `ctx.info()` → usage hints, current status display, lists, neutral info
- `ctx.warn()` → warnings only (something partially worked, caution needed)
- Never mix these up. A usage hint showing how to use a command is always `ctx.info()`, never `ctx.err()`.

Fix these specifically in `cogs/moderation.py`:

**Rule 3 — `on_command_error` in `main.py`:**

`MissingRequiredArgument` currently sends `UI.error()`. Change it to `UI.info()` — a missing argument is a usage hint, not an error state:
```python
# Before

    msg = f"Missing argument: `{error.param.name}`"
# ...
await ctx.send(embed=UI.error(msg))

# After — change only the MissingRequiredArgument case

    await ctx.send(embed=UI.info(f"*Missing argument: `{error.param.name}`*"))
    return
```
